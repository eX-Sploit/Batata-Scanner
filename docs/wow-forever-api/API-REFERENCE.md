Source baseline: **1.60.1 (70374)** at commit **`735496de78ebd30ce816a0637982c556987f258c`**, collected **2026-10-14**. These are migrated source findings, not tests run in WoW. See [evidence boundaries](README.md) and the selected [declarations](api-symbols.jsonl).

## Who queries and observations

The generated declaration provides `C_FriendList.SendWho(filter, origin?, filters?)`; metadata includes `HasRestrictions` and `RequiresFriendList`. `HasRestrictions` alone does not specify a universal hardware-event rule. Batata Scanner conservatively dispatches one query per explicit user action; timers update local state only. A nonthrowing call is not response confirmation. [FriendList declaration](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L330)

`GetWhoInfo(index)` returns a `WhoInfo` table and may return nothing. Its fields include `fullName`, `fullGuildName`, `level`, `raceStr`, `classStr`, `area`, optional `filename`, and `gender`. `GetNumWhoResults()` returns delivered `numWhos` and `totalNumWhos` separately. Missing/inaccessible records or delivered rows below total cannot establish complete coverage. The local saturation threshold is addon policy, not a measured server cap. [GetWhoInfo](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L202), [WhoInfo](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L685), [result counts](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L171)

`WHO_LIST_UPDATE` supplies no query token in this schema. Batata Scanner must preserve its outstanding-request ownership and quarantine late responses after timeout/cancel. `SetWhoToUi(bool)` chooses routing; restoration must account for the exact native event registrations changed. Native coexistence and external-query conflicts require runtime checks. [Event declaration](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L639), [routing declaration](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L395)

`SendWhoFilters` contains class, race, and map arrays. The inspected native Who UI builds excluded class/race choices and included map choices. Do not infer inclusion semantics from field names; verify locale, empty arrays, and combinations before adopting structured filters. [Filter structure](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L666), [native Who implementation](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_GroupFinder_VanillaStyle/Mainline/WhoList.lua)


## Race/class planning

The shared internal race/class roster in [Core.lua](../../Core/Core.lua), used by scanner planning and census presentation, mirrors GuildHQ's pre-removal revision `ef7a9674a5b7c0bd18ce160bba0011cf4f0d29bf`, inspected locally on **2026-10-19**. It covers nine Forever classes and five races per faction, including High Order Skyborne, Windshaper Skyborne, Dwarf Shaman, and Undead Paladin. This is reference-addon data, not a current-client roster test. Batata Scanner owns its copy and has no runtime dependency on GuildHQ.

Subdivision preserves level halving, then selects only the current faction's races compatible with an existing class filter, then only classes compatible with a race filter. Native Who names are matched by `WhoFilter.ID`; absent names fall back to guarded `C_CreatureInfo.GetRaceInfo(raceID)` and finally the reference names. Class names use guarded `GetClassInfo`, localized class globals, then the reference names. Unreadable native choices retain an incomplete-coverage warning. Unsupported class selections are rejected; invalid saved pairs are discarded with incomplete coverage reported.

The pinned declarations specify `WhoFilter.name`/`ID` and an optional `RaceInfo` result containing `raceName`, `clientFileString`, and `raceID`. [WhoFilter](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L676), [GetRaceInfo](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/CreatureInfoDocumentation.lua#L104), [RaceInfo](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/CreatureInfoDocumentation.lua#L165). Mocked tests cover the full matrix in both directions, localization, fallbacks, and saved queries; the actual roster and localized Who matching still require named-build in-game verification.

## Player identity and guild evidence


The generated unit-name schema labels its second return `unitServer`. Camelot's name helpers interpret it as a surname, so preserve full player identity and keep realm scope separate. Do not automatically discard the second return or split every name at a separator. Verify actual first-name/surname and cross-scope behavior in game. [UnitFullName schema](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua#L1224), [Camelot NameUtil](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_FrameXMLUtil/Camelot/NameUtil.lua)

Batata Scanner preserves unknown guild (`nil`), confirmed unguilded (`""`), and a named guild. A passive nil from `GetGuildInfo` does not establish unguilded status. This tri-state and Who precedence are data-quality policy. Missing a legacy global from the selected generated snapshot does not establish removal.

## Access checks

The source declares `canaccessvalue`, `canaccesstable`, `issecretvalue`, and `issecrettable`. A readable outer table does not establish every field is readable. Check access before indexing records and before normalizing, concatenating, sorting, comparing, serializing, keying, or logging externally supplied values. `pcall` may catch a failure but does not declassify data. [Value access](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FrameScriptDocumentation.lua#L65), [table access](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FrameScriptDocumentation.lua#L48), [secret predicates](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FrameScriptDocumentation.lua#L270)

Specific setters can accept secret values without permitting Lua computation on them. Reading a rendered widget is not a declassification path. Batata Scanner's stored census requires ordinary readable records; skip inaccessible observations rather than deriving guessed keys.

## Bounded Who retry policy

Updated **2026-10-20** to recover without asking for a UI reload. This is addon policy, not a new client or server guarantee. An unanswered scanner or external request reaches the configured response timeout, then enters a reply-discard cooldown lasting at least the greater of the query interval and response timeout. Failed or blocked sends, cancellation, and overlapping requests also enter that cooldown. The unfinished chunk remains queued, and all replies during the cooldown are ignored; one late reply does not end the discard window early.

Timers only expire local holds and refresh status. A running, unpaused sweep retries on the next eligible input once the cooldown ends and the native Who list is closed. Manual pauses and stopped sweeps stay paused or stopped. Native routing/listeners are restored on abandonment. Interrupted sweeps remain incomplete because an untagged reply arriving after the cooldown can still be attributed incorrectly; the cooldown must not be described as proof of completion. Named-build verification of late-reply timing and routing remains outstanding.

## Who throttle notification evidence

Researched **2026-10-19**, against the same pinned **1.60.1 (70374)** source only; no current-client or in-game verification. The reported text is "You must wait a moment longer before using /who again". The source does not establish its localized global identifier: `ERR_WHO_LIST_WAIT` remains an unverified candidate. The scanner checks that global if readable and also matches the exact reported English text, with or without a final period.

These are verified **generic notification contracts**, not proof that this throttle uses either event. Payload positions count arguments after `event` in `OnEvent(self, event, ...)`:

| Event | Relevant payload | Pinned primary evidence |
|---|---|---|
| `CHAT_MSG_SYSTEM` | 1: `text`; readability is not guaranteed during chat messaging lockdown. | [Declaration](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua#L2452); [native SYSTEM text handling](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_ChatFrameBase/Mainline/ChatFrameOverrides.lua#L402). |
| `UI_ERROR_MESSAGE` | 1: `errorType`; 2: `message`. | [Declaration](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/SystemDocumentation.lua#L221); [native error handler](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_UIErrorsFrame/Mainline/UIErrorsFrame.lua#L20). |

Treating an exact, readable throttle message during a single outstanding request as rejection is **addon policy**, not a source-backed guarantee that a later result cannot arrive. The scanner preserves its playing or manually paused state, retains the unfinished query, restores native routing, and holds dispatch for at least the greater of twice the configured interval or the configured timeout. A playing scan retries on the next world click after the hold without requiring Continue; timers never dispatch. Reload preserves that state, the queue, and the remaining hold. Unexpected results during the hold are ignored. Ambiguous timeouts, cancellations, and overlaps use the bounded cooldown above; an unrelated or unreadable notification cannot release it early.

A recognized rejection can replace a timeout-only hold with the throttle cooldown for the same unresolved request, preserving its playing or manually paused state. A manual pause requested after timeout is also preserved. Stopping, discarding a late response, detecting an external overlap, or expiry of the timeout hold prevents an old rejection from changing that cooldown. Both the world-click listener and the send path check the configured interval, and the dispatch timestamp is refreshed after `SendWho` returns so preparation and call time cannot shorten that interval. These are mocked local policies, not measured server throttle guarantees.

Named-build runtime verification must record the localized global value, notification routing, and rejection/result ordering, including whether any result arrives after the retry hold. The [untagged result declaration](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FriendListDocumentation.lua#L639) does not settle those questions; mocks only verify the local policy.

## Coroutine compatibility evidence

The browser now uses explicit resumable sorting state. In a **2026-10-20** Lupa Lua 5.1 mock profile, cold search creation for 10,000/50,000 records previously took 24/176 ms; it now measured below the 1 ms timer resolution, with individual preparation/matching steps at approximately 1 ms. Work is distributed across frames rather than eliminated. These measurements do not establish actual client frame times or rendering latency.

Researched **2026-10-20** against the pinned **1.60.1 (70374)** source only. Blizzard's developer console calls `coroutine.create`, `resume`, and `status` while filtering messages, and `coroutine.yield` when its per-frame deadline expires. [Filtering implementation](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_Console/Blizzard_Console.lua#L442), [resume and yield](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_Console/Blizzard_Console.lua#L472). Its [manifest](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_Console/Blizzard_Console.toc#L1) lists the callers and `AllowLoad: Both`; this is load metadata, not a declaration of coroutine access for ordinary addons.

An identifier search of the [pinned archive](https://codeload.github.com/Gethe/wow-ui-source/zip/735496de78ebd30ce816a0637982c556987f258c)'s Lua/XML/TOC/Markdown/text files found coroutine calls only in `Blizzard_Console`, with no `coroutine.wrap` reference or coroutine addon-access declaration. This establishes Blizzard UI usage, not ordinary-addon permission, and does not prove that `wrap` or the library is absent. **Ordinary-addon support for `coroutine.wrap`/`yield` remains unestablished from this source.** Lupa Lua 5.1 support is a harness property, not client evidence; no named-build runtime verification was available.

For bounded browser sorting, prefer explicit resumable sort state with a per-frame work budget rather than a required `coroutine.wrap`/`yield` dependency. Any future coroutine path needs ordinary-addon capability and yield/resume verification on the named build, with a non-coroutine fallback.

## Combat and battleground dispatch holds

Researched **2026-10-20** against the unchanged local source cache at **`735496de78ebd30ce816a0637982c556987f258c`**, **1.60.1 (70374)**; the baseline collection date remains **2026-10-14**. These are pinned declarations/native callers, **not current-client or in-game verification**.

**Recommended synchronous pair: global `InCombatLockdown()` and global `IsInInstance()`.** Use them for a conservative combat-lockdown/battleground dispatch hold, not as proof that lockdown equals every unit combat state.

The native panel manager tests it before denying insecure/addon-origin operations. Use it when unit-combat semantics are specifically required, not as an assumed exact synonym for lockdown. [C_PvP.IsBattleground()](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/PvpInfoDocumentation.lua#L923) also declares a non-nil boolean, with a separate `IsArena()` immediately above it. No native `C_PvP.IsBattleground` caller was found in this cache; the recommended pair avoids that extra namespace dependency.

**Ordinary-addon access and failure policy:** all four declarations belong to `Environment = "All"` systems; none carries `HasRestrictions`, a privileged-only annotation, or a secret-return annotation. This supports ordinary-addon candidates, not guaranteed availability/permission on the installed Camelot client. Capability-check getters and the access predicate, catch call failures, and check [canaccessvalue](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/FrameScriptDocumentation.lua#L65) in the consuming context before branching, comparing, coercing, or logging results. Require readable booleans and a readable instance-type string. Missing capabilities, exceptions, inaccessible values, unexpected `nil`, or malformed results mean **unknown: keep dispatch held**. Do not normalize `nil` to false or use a failed probe as permission to send; `pcall` does not declassify data. The pinned contracts do not establish a legacy nil-as-inactive exception.

**Implemented policy (6.20.0):** use `UnitAffectingCombat("player")` as well as `InCombatLockdown()` so either readable true holds dispatch, without assuming their timings are identical. Both combat getters and `IsInInstance()` must yield readable, correctly typed values before dispatch is permitted. Hold when combat or lockdown is true, the instance type is `"pvp"`, or detection is unknown. Status reads and send paths obtain current values; event handlers only notify. Clearing a hold permits the next eligible user input, never autonomous `SendWho`. Keep manual pause, cooldown/quarantine, queued work, outstanding-result ownership, and native routing rules intact. Hold flags are recomputed, not persisted. Apply this only to Who dispatch; **passive observation remains unchanged**. Event declarations do not guarantee getter ordering during transitions, complete battleground coverage, server acceptance, or combat/arena behavior on the installed build. Those require named-build ordinary-addon runtime checks; neither native callers nor mocks establish them.
